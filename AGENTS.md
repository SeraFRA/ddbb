# AGENTS.md — il metodo di collaborazione di questo repo

Per l'AI che ci lavora e per l'umano che la guida. Nasce da dieci capitoli
 di una collaborazione verificata: le regole qui sotto non sono gusti, sono
 cicatrici. Copialo in altri progetti sostituendo la sezione "questo repo
 specificamente": il resto viaggia.

## Il contratto

- L'umano porta la **direzione come metafora o domanda**, mai come specifica.
- L'AI traduce la metafora in **meccanica**: nome della tecnica nel mondo
  reale, matematica, il più piccolo sistema completo che la realizza.
- Il fine è **capire, non ricevere**: ogni scelta si spiega coi suoi numeri.
- L'AI sbaglia come tutti: quando sbaglia, i bug si documentano. La
  credibilità dell'AI è pagata in post mortem, non promessa.

## Il ciclo (per ogni capitolo o funzionalità)

1. **METAFORE** — parti dalla frase dell'umano, riconoscila, chiamala col
   suo nome nel mondo reale (Bitcask, LSM, MinHash, timing wheel...).
2. **MECCANICA** — implementa il più piccolo sistema completo che la
   realizza; il contesto didattico non scusa finestre tagliate.
3. **MISURA** — numeri confrontati con la teoria, sempre; percentili, non
   medie; il dato onesto anche quando smentisce l'idea.
4. **POST MORTEM** — ogni bug trovato si scrive (a) nel punto esatto del
   codice dove viveva, (b) nel messaggio del commit che lo ripara.

## Le regole dei test (indiscutibili)

- **Stampare non è bloccare**: un test che stampa l'errore senza far
  fallire il processo non è un test. EXIT != 0.
- **Il confronto senza soglia non è un gate**: "0 == 0" non è verde.
  Ogni asserzione quantitativa ha una soglia numerata.
- La demo è il **banco di prova**: ogni invariante ha il suo gate, e un
  contratto rotto ferma tutto.
- Prima di pushare: compila pulito, gira il banco, guarda la CI.
  Il warning non commentato non è letteratura: è un bug latente
  (un `-Wall` in questo repo ha trovato un overflow reale prima del run).

## Il codice

- C11 puro, zero dipendenze oltre la stdlib; `-Wall -Wextra -Wpedantic`
  sempre.
- **Invariants-first**: le regole contrattuali si scrivono PRIMA del
  codice. Otto trappole catturate a tavolino valgono più di otto run
  di debug; e quando una scappa lo stesso, il contratto dice esattamente
  quale asserzione mancava.
- **Una fonte di verità**: tutti i dati derivati (indici, filtri, firme)
  si ricostruiscono da una fonte sola, con una funzione di derivazione
  sola. Nessun derivato contiene puntatori: solo offset.
- **Morte atomica**: ogni cammino che invalida uno stato lo marca e lo
  conta nello stesso istante, in una sola funzione. Chi risponde paga
  un controllo solo.
- L'orologio è del chiamante: niente tempo da muro dentro le decisioni.
- Il formato su disco è un contratto: si cambia solo con un loader che
  legge entrambe le versioni.

## L'onestà come API

- Confidenze dichiarate; ambiguità dichiarata (gruppo dei pari-merito
  invece di fingere certezza); silenzio invece d'invenzione; il "forse"
  del filtro distinto dal "no" dell'indice.
- I limiti si dichiarano in testa al file, non si scoprono in produzione.
- Le decisioni su cosa NON entra sono parte del progetto (l'obitorio):
  una tecnica esclusa col motivo scritto vale quanto una inclusa.

## Questo repo specificamente

- **Lingua**: italiano ovunque — commenti, commit, output dei demo.
  Il README esiste anche in inglese (`README.en.md`).
- `database.c` è il **fossile**: i suoi bug sono didattici, NON si toccano.
- I `database_*.c` sono il **corpus storico**: non si riscrivono; il
  lavoro nuovo va nel motore (`motore.h` + `motore.c` + `demo_motore.c`).
- Build: `make` su Linux, `mingw32-make` su Windows/MSYS2. Banco di prova:
  `./motore_demo` (e ogni capitolo gira da sé, gate incluso). La CI
  ricompila e fa correre tutto a ogni push — con `-Werror` (un warning
  è un bug latente) e il collaudo del motore sotto ASan+UBSan.
- Una workflow si VALIDA col parser prima del push
  (`python -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"`)
  — un due-punti non quotato dentro uno `name:` non fa partire NESSUN
  run: il repo dice "invalid workflow file" e il log manca del tutto,
  perché non esiste nemmeno. (È successo, una volta, qui.)
- Commit: messaggio col post mortem; trailer standard
  `Generated by Mistral Vibe.` + `Co-Authored-By: Mistral Vibe <vibe@mistral.ai>`.
- **Gate caratteri** prima di ogni commit (le mani veloci scrivono
  alfabeti impossibili; qui è successo quattro volte, l'ultima in
  arabo dentro un messaggio — motivo per cui il gate è una WHITELIST:
  una blacklist è sempre in ritardo sull'alfabeto successivo.
  Permesso solo: latino esteso, greco, punteggiatura, frecce,
  matematica, euro):

  ```bash
  perl -CSD -e 'my $h=0; for my $f (@ARGV) { open my $F,"<",$f or next;
    my $n=0; while(<$F>){$n++; utf8::decode($_);
      while(/([^\x00-\x7F])/g){ my $c=$1;
        unless($c =~ /^[\x{00A0}-\x{00FF}\x{00C0}-\x{024F}\x{0370}-\x{03FF}\x{2010}-\x{2027}\x{2190}-\x{21FF}\x{2200}-\x{22FF}\x{20AC}]$/){
          print "$f:$n: U+" . sprintf("%04X", ord($c)) . "\n"; $h++; } } } }
    print $h==0?"PULITO\n":"FALLITO $h\n";' $(git ls-files)
  ```

- Su Windows il Device Guard può bloccare le exe appena compilate nella
  cartella del progetto (exit 126): attendere alcuni secondi, o compilare
  fuori dalla cartella.
- **L'hook `pre_agent`** (`.vibe/hooks.toml` → `prefetch_hook`, capitolo 12)
  gira a ogni turno e parla col motore: se si rompe `prefetch.c`, l'hook
  tace (fail-open, per contratto) ma `demo_prefetch` in CI diventa rosso.
  Lo staging (`*.prefetch`) è un derivato: gitignored, mai nel repo.
- **La memoria di lavoro** vive nel motore via MCP (server `motore`,
  file `memoria.db`, gitignored). Il repo è la verità durevole e la
  memoria NON la duplica: dentro va ciò che non è ancora nel repo —
  lavori in corso, scoperte non scritte, decisioni in bilico. La morte
  è esplicita: quando una cosa entra nel repo (commit), la voce si
  cancella con `del`. L'orologio della memoria è FERMO (il server parte
  a tick 1 e non si avanza mai): il file PDB1 non porta il clock, e un
  tick di partenza statico non può essere monotonic tra riavvii — le
  voci nate a un tick sopra la partenza morirebbero al load per wrap
  dell'aritmetica. Il TTL contato in sessioni sta nell'obitorio: vuole
  il tick dentro il file (formato v2, col loader che legge entrambe).
  Chiavi a namespace (`in-corso/...`, `nota/...`): l'intervallo le
  lista per prefisso. Dopo scritture che pesano: `salva`. L'onestà è
  quella del motore: confidenza dichiarata, silenzio invece di
  invenzione.
